# 前端产品说明

## 产品目标

界面服务于不懂编程的网球教练、场馆人员和甲方验收人员。用户不需要理解模型、阈值或命令行，
只需完成“选择视频 → 等待分析 → 查看复盘”三步。

## 核心流程

1. 首页只保留一个主任务：上传比赛视频。
2. “真实比赛样例”直接使用冻结算法产物，演示数字全部从 `scene3d.json` 计算。
3. 分析过程使用四个中文阶段解释当前进度，不向用户暴露内部模块名。
4. 报告先给结论和关键数字，再提供视频、事件、落点图、三维视图和可信度说明。
5. 点击任意事件即可跳到对应视频时刻；分析标记可随时开关。
6. 顶部“冻结模型 · 纯推理”表示上传期间不会训练或改变 BallNet 参数。

## 实时落点实验台

`web/live-lab.html` 是直播方案的内部对比实验入口，不替代现有上传分析首页。

- “真实端到端实验”默认使用内置 Demo，也允许“上传其他视频”。上传素材先由本地可信
  服务验证，再启动临时 L40S；模型准备完成后由本机视频模拟摄像头，以原始速度编码到
  RTMP，经配置的 ZLMediaKit 分发给 L40S 拉流。测试视频不会上传到推理服务器。左屏直接
  播放 ZLMediaKit 生成的 HTTP-fMP4 连续媒体流，不受推理队列
  速度影响；后端 JPEG 端点只保留为诊断接口，不再承担正常预览。当前公网媒体机的
  WebRTC UDP 路径未通过实测，因此实验台优先使用延迟略高但稳定的 HTTPS/TCP 播放。
- 推理结果不从 L40S 直接返回本机。L40S 将经过认证的状态与落点 JSON 写入同一台 ECS 上
  独立的结果中继服务，本机只从该服务拉取；结果中继不可用时明确失败，禁止直连降级。
  ZLMediaKit 仍然只负责媒体流，不承担 JSON 存储。
- 流式工作线程不读取候选或报告缓存；它在线执行冻结 RacketVision、YOLO 人物检测、
  固定窗口跟踪与因果落点判定。球场和中值背景在开流前为固定机位准备一次。
- 摄像头时间来自已拉回的帧数，分析时间来自模型已经处理的帧数；二者差值是真实积压，
  不允许用可调滑块或预设常数代替。
- 媒体读取和推理必须解耦。即使 GPU 跟不上 30fps，也要把每个到达帧排队处理并在结束时
  核对拉流帧数与处理帧数，禁止通过直播缓冲区静默丢帧来伪装实时。
- 实验结束后，才使用冻结 `scene3d.json` 作为评测真值做时空匹配；该文件不能驱动在线事件。
- “离线基准回放”保留旧的因果显示基准，明确标为非链路实测，便于和真实实验对照。
- 上传、L40S 冷启动和素材传送属于实验准备时间；画面真正开始后才计算摄像头时间、分析
  时间与积压。任意结束路径都必须释放临时实例，页面不得持有 PPIO 密钥。

## 可视化约定

- 近端球场始终位于落点图下方，远端位于上方。
- 界内落点使用荧光绿色；界外落点使用红色叉号。
- 落点图只展示落点，不叠加轨迹线。
- 界内率、最常落区、平均底线距离、轨迹覆盖率均来自真实分析文件。
- 三维视图中的界外球不点亮任何场内区域，只保留落点标记。
- 用户选择透视矫正时，报告通过 WebGL 对原视频实时使用与预览相同的矩阵；球场和两侧球员保护带必须留在画面内，落点层在矫正后绘制。

## 输入约定

- 不限制用户上传帧率；24、25、29.97、30、50、60、120fps等有效原生帧率均可分析。
- 29.97/30fps只是回归验收基线。高帧率包含更多高速运动与触地瞬间，但逐帧计算量也会按比例增加。
- 不通过人工插帧制造检测证据；高帧率必须来自相机原始素材。
- 推荐固定高位底线机位、横屏、1080p 或更高分辨率。
- 浏览器支持 MP4、MOV、WebM 和 MKV，单文件上限 4GB。

## 维护边界

算法边界记录在 `docs/CURRENT_ARCHITECTURE.md`。常规前端迭代只允许修改 `web/`、展示文案、
只读报告和可视化资源，不得调整跟踪、轨迹、落点或规则判断。
