## 本次评估目标

先阅读代码，评估把「上传视频分析」和「实时/伪直播分析」接入团队 App 的工程量。
**初步评估不需要安装模型、开通 GPU、配置 API Key 或把整套服务跑起来。**
遇到确实无法通过代码回答的问题，再列出需要的小规模联调；不要先要求同事安装全部环境。
需要实际运行时，另见 [Agent 配置指引](TEAM_AGENT_SETUP.md)。

默认评估路径是 **App 采集/上传/播放，服务端运行算法，App 展示结果**。
将模型直接放到手机端推理不属于现成能力，需另列模型转换、硬件适配、功耗和精度评估，不能混入普通接口接入报价。

## 当前系统与 App 目标结构

```text
现在：浏览器 → 同事电脑上的 Python 服务 → 临时派欧云 GPU → 分析结果
直播：本机 FFmpeg → ZLMediaKit → GPU 拉流分析 → ECS 结果中继 → 本机服务 → 浏览器

待评估：App → 团队业务后端（承接现有本机服务职责）→ 临时 GPU
        App/摄像头 → 媒体服务 → GPU → 结果服务 → App
```

最重要的工程差异：当前 Python 服务运行在个人电脑上，承担密钥保存、任务调度、
文件保存、云端资源回收和结果转发。正式 App 不能只搬页面，还需要为这些职责安排服务端部署。
派欧云 Key、镜像凭据和内部中继 Token 不应放进 App 安装包。

## 两条流程要接哪些接口

### 上传视频分析

- App 选择/录制视频，调用 `POST /api/analyze`，传入文件与元数据。
- 查询 `GET /api/status`，处理运行、需确认球场、完成、失败等状态。
- 需要时展示标定参考图，按近左、近右、远右、远左顺序提交 `POST /api/court-calibration`。
  注意离线标定与直播角点接口的具体坐标单位，不能仅因都叫 corners 就直接复用请求。
- 读取报告与源视频，展示轨迹、落地区域、回合小地图和事件列表。
- 历史接口为 `GET /api/history` 和 `DELETE /api/history/{job_id}`；当前底层是本机文件，正式 App 需要服务端存储和用户归属。
- 云端分片上传目前是中继到 GPU 的内部机制；不能据此宣称 App 上传已支持断点续传。

### 伪直播 / 真正直播

- 目前伪直播是「上传一个文件，再由电脑 FFmpeg 按原速推流」，不是手机摄像头 SDK。
- 客户端通过 `/api/live-lab/upload` 或 `/api/live-lab/start` 启动，通过
  `/api/live-lab/status?session_id=...&after_event=N` 读取状态和增量事件，通过 `/api/live-lab/stop` 停止。
- 当前正常画面使用媒体服务的 HTTP-fMP4 播放；配置中的 WebRTC 名称不等于已完成手机 WebRTC 接入。
- 真直播还要评估手机采集/编码/推流、推流授权、断线重连、前后台切换、音视频权限，以及播放画面与分析事件的时间同步。
- 现有 live-lab 是内部实验接口，不能直接视为可面向多用户发布的稳定 App SDK。

完整请求字段、响应和鉴权边界请查 [API 文档](API_AND_SCHEMAS.md)及接口实现，本文不是第二份协议定义。

## 已知限制，必须计入估算

- 当前以单机位、已确认球场为前提；复杂机位、遮挡和剪辑需要额外验证。
- 当前上传分析服务按单个活动任务设计；多人并发不是现成能力。
- 当前球场首次校正后每 300 秒校正一次；镜头移动可能到下一周期才纠正叠加位置。
- 落地判断和回合切分仍有误差；演示可运行不等于算法达到所有产品验收标准。
- 长视频曾出现阶段长时间无细分进度，以及读取云端状态失败；恢复能力和耗时需单独实测，不能只报界面集成工时。
- 当前临时 GPU 启动命令包含两小时上限，不能直接承诺无限时长直播。
- 个人电脑的历史文件、环境变量和忽略配置不会随克隆仓库迁移；生产部署需替代这些依赖。
- 模型和运行数据不随 Git 完整分发；代码阅读足够初评，运行时按模型清单安装并取得私有镜像权限。
- 商用分发及第三方依赖授权仍需按 [发布检查表](PUBLICATION_CHECKLIST.md)评估，不能把源码可见等同于授权已完成。
