# 给接手 Agent：在同事电脑上运行分析与伪直播

你的任务是把本仓库配置到可运行状态，而不只是告诉使用者安装什么。目标有两个：

1. 上传比赛视频，完成云端分析并打开复盘报告。
2. 上传视频模拟直播，看到直播画面与持续更新的分析结果。

本文按 Windows + PowerShell 编写。先确认操作系统；其他系统不要直接执行 Windows 命令。
项目根目录是包含 `AGENTS.md`、`setup.ps1` 和 `run_ui.ps1` 的目录，不是它的上级目录。
先读 `AGENTS.md`，按其中的文档顺序了解当前实现。本文负责新电脑配置，不要求改算法。

## 一、先自动检查并安装，不要逐项让使用者代劳

- 检查 Git、Python 3.12、FFmpeg、FFprobe 和浏览器是否可用。
- 缺少的软件，在具备权限时从官方渠道或可信软件包管理器安装；需要管理员操作时才请使用者介入。
- FFmpeg 需要支持 `libx264` 和 RTMP；确保 FFmpeg、FFprobe 加入 PATH，并刷新当前进程环境。
- 默认使用云端推理，同事电脑不要求 NVIDIA 显卡。仅为前端联调，不必安装本地 CUDA 或 Docker。
- 这是静态 HTML/CSS/JavaScript 前端，正常运行不需要 `npm install`。Node.js 用于开发检查和部分测试。
- 不复制原开发者的 `.venv`，在新电脑创建自己的环境。

在项目根目录执行：

```powershell
.\setup.ps1 -Accelerator cpu
.\.venv\Scripts\python.exe tools\verify_install.py
```

`setup.ps1` 安装 Python 依赖、安装项目并下载/校验模型，但不替你安装 Python 和 FFmpeg。
当前安装流程会校验本地模型；不要因为使用云端就擅自跳过。下载失败时，优先排查网络；
如果团队提供了离线模型目录，使用 `setup.ps1 -Accelerator cpu -AssetSource <实际目录>`。
逐步检查命令退出码，解决可自动修复的问题；不要把前一步失败当作安装成功。

## 二、向使用者一次性索取真正缺少的配置

先检查已有配置是否存在，只报告“已配置/缺失”，不要打印密钥值。已有可用配置不要覆盖。
把剩余问题合并为一次提问，使用下面清单：

| 配置 | Agent 应如何处理 |
|---|---|
| 派欧云（PPIO）API Key | 由同事或团队管理员提供；需要在实际使用账号下取得，不能自行猜测 |
| 生产镜像地址和访问权限 | 先读 `src/netcast_tennisvision/cloud/ppio_lifecycle.py` 的默认值；确认账号能拉取该镜像，尤其是换用个人账号时 |
| 云端鉴权 Token | 若新建独立本地中继与临时 GPU 链路，可由 Agent 用密码学随机数生成并安全保存；若团队规定已有 Token，使用团队提供值 |
| ZLMediaKit 主机地址 | 伪直播必需，由团队管理员提供；复用团队服务，不擅自新建服务器 |
| ZLMediaKit WebRTC 播放入口 | 伪直播必需，由团队管理员提供准确地址，包括必要的路径前缀 |
| ECS 结果中继 URL、Token | 伪直播必需，由团队管理员提供；Token 必须与现有中继服务一致，不能只在本机随机生成 |

这里不需要 OpenAI API Key。运行这两个功能所需的云服务是派欧云，以及团队的媒体/结果中继服务。
如果账号尚未开通、没有可用算力额度、没有私有镜像权限，清楚列出需要管理员处理的具体事项。
不要让前端同事误以为只填任意一个派欧云 Key 就能访问团队的所有云端资源。

## 三、Agent 写入本机配置

普通云端分析使用以下环境变量：

| 变量 | 内容 |
|---|---|
| `TENNISVISION_CLOUD_PROVIDER` | `ppio` |
| `PPIO_API_KEY` | 用户提供的派欧云 Key |
| `TENNISVISION_CLOUD_TOKEN` | 本地中继与临时 GPU 之间的鉴权 Token |
| `TENNISVISION_PPIO_IMAGE` | 团队确认可用的生产镜像完整地址 |

Windows 上写入当前用户级环境变量，并同步到当前进程，或重新打开终端。
`run_ui.ps1` 会读取上述用户级配置。按需创建 GPU 的标准路径不需要固定的
`TENNISVISION_CLOUD_URL`；如发现遗留值，确认用途后清除或调整，避免误连旧服务。
本文编写时生产版本为 `production-v30`；接手时以代码与团队实际发布版本为准。

伪直播建议写入被 Git 忽略的 `data/live_lab_config.json`，示意如下：

```json
{
  "zlm_host": "团队提供的媒体主机",
  "zlm_webrtc_origin": "团队提供的完整播放入口",
  "result_relay_url": "团队提供的结果中继基础地址",
  "result_relay_token": "团队提供的中继鉴权 Token"
}
```

不要把示例占位符当作真实配置。写入前保留已有有效字段，并确认该文件没有被 Git 跟踪。
代码也支持 `TENNISVISION_ZLM_HOST`、`TENNISVISION_ZLM_WEBRTC_ORIGIN`、
`TENNISVISION_RESULT_RELAY_URL`、`TENNISVISION_RESULT_RELAY_TOKEN` 环境变量；
若使用它们，必须确保启动后端的进程实际继承了这些变量。环境变量优先于 JSON 配置。
地址具体格式以 `streaming/live_experiment.py`、`cloud/ppio_lifecycle.py` 和团队部署为准。

真实密钥只放本机配置或团队认可的凭据存储中，不写入文档、Git、浏览器 JavaScript、截图或诊断输出。
需要使用者输入秘密时，优先用本机安全输入方式，不要求粘贴到共享聊天中。

## 四、启动与验收

```powershell
.\run_ui.ps1
```

使用启动器输出的实际地址，端口可能是 4173–4183，不要硬编码。
普通分析入口为 `/web/`，伪直播入口为 `/web/live-lab.html`。
必须同时运行本地 Python 后端，不能双击 HTML 文件代替启动。它负责上传、云端任务和结果转发。
运行期间保持本地服务和电脑在线；浏览器页面可以关闭，但不要因此结束后端进程。

按顺序验收：

1. 环境自检通过，页面能打开，`/api/status` 可访问，确认走 `cloud-on-demand`。
2. 检查媒体服务和结果中继的可达性、鉴权；健康检查通过不等于整条链路已通过。
3. 确认使用者已授权短时 GPU 联调后，用团队提供的短视频或仓库演示视频做一次真实上传分析。
   四角标注需要时请使用者核实，不随意替人猜角点；确认最终能打开报告。
4. 做一次短时伪直播：确认有播放画面、分析时间持续推进、结果持续更新，测试后停止会话。
5. 确认两次测试产生的临时 GPU 已释放；不能只看页面“完成”就宣称验收通过。

不要直接用 40 分钟视频做首次验收。当前两条分析路径首次对齐后每 300 秒校正一次球场，
间隔内复用坐标；镜头中途移动可能暂时错位。这是当前行为，不要擅自改回逐帧完整对齐。

## 五、交付结果必须具体

最后给同事一张简短状态表：安装完成项、配置完成项（不含秘密）、两个入口地址、
普通分析实测结果、伪直播实测结果、GPU 释放情况，以及尚需人工处理的事项。
若缺凭据，先完成所有不依赖凭据的安装工作，再明确说明缺哪一项、找谁提供、拿到后如何继续。
没有实际跑通时，必须写“环境已配置，云端联调未完成”，不能写“两项功能均已可用”。

更深入排错：查看 `docs/API_AND_SCHEMAS.md`、`web/README.md` 和当前源代码。
