# Cloud end-to-end speed verification

## Root cause and fix

Live image-to-world inversion produces a world-to-image homography with a negative
(2,2) entry for flat2. Offline fitting chooses a positive gauge. They describe the
same projection, but camera recovery previously converted the negative gauge to
negative camera height and rejected it. At640x360, normalizing by H[2,2] recovers
camera height1.4332785m. This directly reproduced the bug without performance testing.
Speed now normalizes its own copy; tracking geometry defaults remain unchanged.
Signed-scale synthetic tests and complete pytest pass. Native high demo regression
leaves every non-speed scene field identical, including manual review windows.

## Protocol

PPIO NVIDIA L40S.22c125g, isolated production-v30 container with current source.
flat2 first90s, native30fps1080p source copied without excerpt recompression.
Cloud FFmpeg-re -> external ZLMediaKit RTMP -> maintained live worker at640x360
-> actual ball/person/pose inference -> speed -> authenticated HTTP collector
-> localhost verification page. Pose on in all four off/on/on/off arms. Speed
runs synchronously for this measurement; no caches or fabricated speed outputs.
Overlapping30-frame supports advance10frames, waiting12 arrived frames for
tracker maturity. Local contact candidates split supports; confidence thresholds
unchanged. Duplicate accepted midpoint times within0.3s suppressed.

Full production live integration is not deployed: experiment-only process hooks
and a dedicated verification page exercise the result path. This is not a
camera-to-WebRTC-display glass-to-glass measurement or a speed-accuracy validation.

## Failed attempt retained

outputs/speed_cloud_e2e captured a collector KeyError after real speed output began:
progress snapshot included an event before its latency field was assigned. Instance
released. v2 publishes only complete event dictionaries and collector also skips
incomplete rows. Failed data not included in ABBA statistics.

## Evidence

outputs/speed_cloud_e2e_v2 contains exact uploaded source/payload, remote results,
client_events.json, review.html and instance.json. Browser was inspected while it
was receiving real speed values. Timing fields are relative to worker stream
initialization (not original camera hardware PTS). Batch-last delay excludes earlier
frames' batch wait and precedes landing publication. Server speed delay is relative
to fitted flight midpoint and includes maturity/lookahead. snapshot_age_ms includes
remote progress publication and collector poll wait, measured at remote response
snapshot; it excludes remaining network transit and browser paint. Poll RTT is
recorded separately. Do not relabel it as exact glass-to-glass latency.
