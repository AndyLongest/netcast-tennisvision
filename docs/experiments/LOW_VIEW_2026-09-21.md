# Low-view full-video experiment (2026-09-21)

This is an isolated review experiment, not a production algorithm switch or a cloud release.
Input: archived `flat_deemo.mp4`, job `6c731f96161c448f9227f07c1643003e`,
960x544, native 30fps, 6982 frames. Reuses the report's four original court corners;
low-view baseline height ratio is 0.25458. Hardware: local RTX 3050 Ti Laptop 4GB.

## Method

Both passes run the maintained notebook in isolated output/cache directories, with the
same saved calibration and frozen RacketVision weights. The comparison first runs the
existing pipeline. The experimental pass runs the same model on a lossless far-court
crop at every native frame. Crop proposals fill missing full-frame candidates, or replace
a spatially agreeing candidate when crop confidence is greater; conflicting full-frame
observations are preserved. Tracker association still decides accepted ball positions.

The optional `events/occluded_landing.py` detects short missing-observation intervals
(up to 0.20 seconds) within a single track, with at least three real observations on
each side, using the existing smooth-versus-impulse model. It requires strong upward
impulse evidence, bounded residual and BIC gain, excludes nearby hits, existing bounces
and camera-registration jumps. It uses up to 0.30 seconds of post-event evidence.
No ball observations or existing events are rewritten. Extra inferred events carry
no court position, are exported separately and appear only as an amber review caption.
They never create a minimap point, yellow zone or rally boundary.

## Review and limits

Output: `outputs/flat_low_view/review.html` and `flat_deemo_low_view.mp4`.
The full annotated video has no trajectory tail, and preserves source audio when present.
Output frame count is checked by decoding the full result. `summary.json` records event
counts and ball coverage; these are not accuracy scores. Human landing labels have not
been supplied for this clip. This offline test does not measure source-paced latency.
The source contains cuts/motion while the existing report contains only one court
keyframe: its geometric limitations remain in both runs. No newly trained pose/ball
model is introduced; existing hit evidence rejects racket-confounded intervals.

## Reproduce

```powershell
.venv\Scripts\python.exe tools/experiment_far_court_roi.py --video data/history/6c731f96161c448f9227f07c1643003e/source.mp4 --reference data/history/6c731f96161c448f9227f07c1643003e/scene3d.json --out outputs/flat_low_view --low-view
.venv\Scripts\python.exe tools/render_low_view_review.py --out outputs/flat_low_view --source data/history/6c731f96161c448f9227f07c1643003e/source.mp4
```

Rollback: do not call the experiment. No production notebook, tracking or landing rule
is changed by this experiment; the new module is imported only by the developer tool.

## Measured results

- Baseline: 3225 detector-backed frames, 5474 positioned frames, 50 landings.
- Experiment: 3942 detector-backed frames, 6113 positioned frames, 58 landings plus 2 unpositioned inferences at 122.50s and 134.97s.
- Full delivered video decoded successfully: 6982 frames.
- Baseline landing times match the archived report exactly. Native high-view regression
  retained every pre-existing scene field, including all manual-review timestamp windows.
- Four focused synthetic tests and the full suite passed; Ruff and handoff checks passed.
- The two gap-inference windows were inspected as frame sequences; they remain inferred
  rather than independently labelled confirmed touchdowns.
